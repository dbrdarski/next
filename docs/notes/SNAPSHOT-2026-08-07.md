## 1. Resolved

### 1.1 Author rulings implemented

**`++` is concatenation** — split from numeric `+`, then extended to tuples
(`6f56fd0`, `aa0fab1`).

This closed a live unsoundness rather than adding a feature. With one overloaded `+`, μ §8's
commutative reordering could rewrite *string* concatenation, so two functions that spelled a
seam differently canonicalized to one shape and interned to one value — **defining one
function changed what another computed**:

```
g = (s) => "y" + s ; g("x")                        →  "yx"
f = (s) => s + "y" ; g = (s) => "y" + s ; g("x")   →  "xy"    ← f changed g
```

`(s) => s + s` also compared equal to `(s) => 2 * s`, though the second traps on a String.
The frozen rewrite list needed no amendment — the rewrites were never wrong about arithmetic,
they were wrong about what `+` was. Tuple support later unblocked GR-29.

**Principle 9 stamped** — unproven termination is an error. Already implemented before today;
found and verified, and the docs corrected: the termination spec still reads "warns and
compiles, leaning: error," and is manifest-protected, so the ruling supersedes it.

### 1.2 Soundness fixes — the compiler was *wrong*, not merely incomplete

| Defect | Symptom | Commit |
|---|---|---|
| Termination reached only direct callees | `wrap = (k) => [spin(k)]` **compiled**; every act body too, since acts are blocks | `a5c4e95` |
| Local functions did not resolve | a function defined in a block was invisible to the **whole** analysis, termination included | `21573fa` |
| RT-09's memo key erased parameter spelling | analyzing one program **changed the verdict of the next** | `a30529f` |
| Block groups rebuilt per analysis pass | four distinct values for one source function — an identity-law violation | `685b7ae` |

**On the first:** `ground_demand` opened with `if !is_recursive(callee) { return; }`, which asks
whether a callee is *itself* on a cycle. A seat that merely **reached** a diverging function was
never checked. Fixed by late resolution — walk the body under the domain that arrived and
adjudicate what it actually calls, with the arguments those calls actually receive. Carrying the
arguments down is what keeps `run = (n) => [countDown(n)]` at `run(5)` accepted; grounding over
`Top` would have rejected it.

**On the third:** `InstanceKey` is built from the **α-renamed** shape, so `(n) => … n …` and
`(k) => … k …` key identically — while a cached row's `result` is an expression in the
*original* spelling. The analyzer bound `k`, the rows referenced `n`, nothing resolved. An
earlier fix that cleared caches per compilation was **expiry, not memoization**, and was
reverted on the author's objection. The real fix completes the key. Net −31/+20 lines.

### 2.2 The body-safety gap is two gaps

**A — multi-parameter recursion.** Only `gcd`'s swap shape passes:

```
gcd = (a, b) => b == 0 ? a : gcd(b, a % b)      → compiles
f   = (a, b) => b == 0 ? a : f(a, b - 1)        → REJECTED, at grounding first
f   = (a, b) => a == 0 ? b : f(a - 1, b)        → REJECTED, at grounding first
f   = (a, b, c) => c == 0 ? a : f(a, b, c - 1)  → REJECTED, at grounding first
```

These fail at **grounding**, before body safety is reached — so fixing body safety alone would
not make any of them compile. Feature-sized work across two subsystems.

**B — locally-defined recursion.** Narrow and clean:

```
cd = (k) => k == 0 ? 0 : cd(k - 1) ; r = cd(5)                → compiles
cd = (k) => …  ; run = (n) => { cd(n) } ; r = run(5)          → compiles
run = (n) => { cd = (k) => k == 0 ? 0 : cd(k - 1) ; cd(n) }   → REJECTED
```

Single parameter. Grounding says **Grounded** in all three. The only variable is *where the
function is defined*. Non-recursive locals prove fine, so it is local **and** recursive together.

Two hypotheses tested and **both refuted**: the local closure does *not* fall back to a `Solo`
group identity (it is `Group siblings={"cd"}`, same as module-level), and unstable closure
identity — real, and genuinely fixed — was not what blocked it.

**Next probe:** `safety::discover` / `settle` — whether the self-call resolves to the same node
as the seed or spawns one that never converges. `covering_node` is the place to look.

## 3. Method notes

Three errors this session shared one root: **conclusions stated before measurement**, and each
error made the work sound more finished than it was.

- The trap-class residue was called "narrow, all `OperationSafety`" — measured, 44 of 84 chains
  changed class.
- The termination hole was reported twice at the wrong size: "the mutation world is uncovered,"
  then "act bodies aren't walked." It is neither — any diverging call inside a larger
  expression, `[spin(k)]` included.
- `Refutation.witness` being a `Rational` was named as the blocker for GR-03A/GR-22B. The real
  answer is that GR-11's refutation route was never implemented; the field type is a consequence.

And one method failure the author caught directly: a fix was added, the **outcome** was checked
(did the verdict change?), the **mechanism** was not (did it do what it claimed?), and it was
reverted on that basis. Re-run with the mechanism instrumented, it worked exactly as claimed —
so the reversion had been reasoning from an unverified premise.

**The standing rule, now written into `DECISIONS.md`: verify the change did what it claims
before reading what it changed.**

**A caution on this session's numbers.** Several probes ran multiple programs in one process,
and before `a30529f` that could give a wrong reading — at least one case first reported as
rejected is accepted in isolation. Conformance rows, and anything re-measured in a fresh
process, stand. Loose probe output from earlier in the session should be re-run before it is
trusted.
